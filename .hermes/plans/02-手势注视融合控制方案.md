# MotionControl — 头手融合光标控制 + 手势动作映射方案

> 状态：设计稿（待评审）
> 版本：v1

---

## 一、核心理念

**光标定位靠手，头选区域，手势按动作。**

- **头（注视）** → 圈定屏幕上的**区域**
- **手指** → 在区域内**精确定位**光标
- **手势（预定义）** → 触发**动作**（单击/双击/拖拽/滚动）

≠ 传统头控鼠标（全程转头），≠ 纯手势控制（抬手累），而是**两者互补**。

---

## 二、光标控制模型：双层定位

### 2.1 第一层：头部姿态 → 屏幕区域

头部姿态（yaw/pitch）从原来的"精确定位到像素"改为"定位到屏幕区域"。

```
屏幕划分为 3×3 网格（共 9 个区域）：
┌──────────┬──────────┬──────────┐
│  区域A    │  区域B    │  区域C    │   ← 左转头
│  左上     │  中上     │  右上     │
├──────────┼──────────┼──────────┤
│  区域D    │  区域E    │  区域F    │   ← 正对屏幕
│  左中     │  中心     │  右中     │
├──────────┼──────────┼──────────┤
│  区域G    │  区域H    │  区域I    │   ← 右低头
│  左下     │  中下     │  右下     │
└──────────┴──────────┴──────────┘
```

yaw/pitch 从精确值变为阈值判断：

| yaw 范围 | pitch 范围 | 对应区域 |
|----------|-----------|---------|
| < -0.1 | < -0.1 | A（左上） |
| < -0.1 | -0.1 ~ 0.1 | D（左中） |
| < -0.1 | > 0.1 | G（左下） |
| -0.1 ~ 0.1 | < -0.1 | B（中上） |
| -0.1 ~ 0.1 | -0.1 ~ 0.1 | E（中心） |
| -0.1 ~ 0.1 | > 0.1 | H（中下） |
| > 0.1 | < -0.1 | C（右上） |
| > 0.1 | -0.1 ~ 0.1 | F（右中） |
| > 0.1 | > 0.1 | I（右下） |

> 阈值 0.1 rad ≈ 6°，轻微的头部转动即可切换区域。
> 用户只需要微微转头就能切换到目标区域，不需要大幅度转动。

### 2.2 第二层：指尖位置 → 区域内精确定位

头部选好区域后，**指尖（食指指尖）的实时位置**在该区域内精确定位光标。

```
指尖位置（归一化 0~1） → 缩放映射到选定区域的像素范围

例如：
- 头部选定区域E（中心区，x: 1/3~2/3 屏幕宽, y: 1/3~2/3 屏幕高）
- 指尖 x=0.2 → 光标 x = 1/3 + 0.2 × (1/3) = 0.467 屏幕宽
- 指尖 y=0.8 → 光标 y = 1/3 + 0.8 × (1/3) = 0.6 屏幕高
```

**关键点**：
- 指尖在摄像头画面中的**绝对坐标**决定光标在区域内的**相对位置**
- 手不需要悬停在一个位置不动，可以在区域内自由移动来控制光标
- 手上的微抖动会被区域缩放比抑制（区域越小，手指移动覆盖的像素越少，越稳定）

### 2.3 两层配合的用户体验

```
用户操作：看右下角 → 抬手到右侧 → 食指微调 → 光标精准定位到右下角的关闭按钮

头部：微微向右下看 → 区域 I（右下角）被选中
手指：食指在画面右侧 → 光标在区域 I 内部精确定位
画面反馈：区域边界半透明显示 + 光标在区域内移动
```

## 三、摄像头位置标定

### 3.1 为什么需要标定

摄像头放在显示器上方、下方、左侧、右侧，都会改变"直视屏幕"对应的头部姿态基线。

```
摄像头在显示器上方：
    用户平视时，视线方向是略微向上看的 → pitch 偏大
    需要记录一个 baseline offset

摄像头在显示器下方：
    用户平视时，视线方向是略微向下看的 → pitch 偏小

摄像头在侧面：
    用户平视屏幕中心时，头实际是略微转向摄像头的
```

### 3.2 标定流程（首次使用 / 调整摄像头后）

```
步骤1：用户正对屏幕中心，保持自然坐姿
步骤2：点击"标定"按钮
步骤3：系统记录当前 yaw_offset 和 pitch_offset（维持 2 秒取平均值）
步骤4：后续所有头部姿态数据都减去这个偏移量
```

实现方式：给 `GazeEstimator` 增加一个 `calibrate(yawOffset:, pitchOffset:)` 方法。

### 3.3 可选进阶

支持"跟随标定"：在用户使用过程中持续微调基线（用平滑均值漂移，类似手机屏幕的自动亮度调节）。

## 四、手势 → 动作映射（Phase 1 基础版）

### 4.1 预定义基础手势

| 编号 | 手势 | 触发条件 | 映射动作 |
|------|------|---------|---------|
| 1 | **Pinch（捏合）** | 拇指尖与食指尖距离 < pinchThreshold ≥ 200ms | **单击鼠标左键** |
| 2 | **快速双击 Pinch** | 两次 Pinch 间隔 < 400ms | **双击鼠标左键** |
| 3 | **Pinch + 移动** | Pinch 保持 + 手移动 > 移动阈值 | **拖拽**（按住左键移动） |
| 4 | **释放 Pinch** | Pinch 结束（手指分开） | **释放鼠标左键**（拖拽结束） |
| 5 | **握拳 Fist** | 指尖全部靠拢（五指收拢） | **右键单击** |
| 6 | **手掌 Open** | 五指全部伸直张开 | **取消/释放** |
| 7 | **食指指向 Point** | 仅食指伸直，其余握拳 | **悬停/选中**（不点击） |
| 8 | **挥手方向 Swipe** | 手掌整体水平/垂直移动 | **滚动**（方向对应上下左右） |
| 9 | **三指 Pinch** | 拇指+食指+中指三指捏合 | **Mission Control / Exposé** |

### 4.2 手势优先级

当多个手势可能同时满足时，按优先级匹配：

```
Point (食指指向) > Pinch (捏合) > Fist (握拳) > Open (手掌) > Swipe (挥动)
```

优先级高的手势先匹配，匹配成功后不再检查低优先级手势。

### 4.3 新增系统反馈

- 光标切换样式：不同手势下光标改变形状（Point → 十字准心，Pinch → 手型抓取）
- 手势成功触发时，画面角落闪烁提示（如 "Click ✅"）

### 5.2 CursorController 核心逻辑

```
输入: gazeRegion (区域ID), fingertipPosition (指尖归一化坐标)
输出: cursorScreenPosition (屏幕像素坐标)
逻辑:
    1. 根据 gazeRegion 计算区域在屏幕上的 pixel rect
    2. 将 fingertipPosition (0~1) 映射到 pixel rect 内
    3. 应用平滑滤波 → 输出最终光标位置
    4. 通知 UI 绘制区域边界
```

#### 5.3 GestureAnalyzer 改造

当前 `GestureAnalyzer` 只输出一个手势类型字符串，需要改为输出**结构化手势事件**：

```swift
struct GestureAction {
    let type: GestureType       // .pinch, .fist, .point, .swipe, .open
    let state: GestureState     // .began, .changed, .ended
    let duration: TimeInterval
    let position: CGPoint
}
```

这样可以区分"捏合开始"（点击）和"捏合保持+移动"（拖拽）。

## 六、Phase 2 扩展（远期）

### 6.1 自定义手势录制

用户操作流程：
1. 打开手势录制面板
2. 在摄像头前做一次手势（如"竖大拇指"）
3. 系统录制该手势的**关键点特征向量**（20个手部关键点的相对位置）
4. 用户为该手势绑定 macOS 动作（如"切换桌面"）
5. 后续检测到该手势即触发绑定的动作

### 6.2 绑定 macOS 原生快捷指令

支持的动作类型：
- 通过 `osascript` 执行 AppleScript 脚本
- 触发 macOS Shortcuts.app 中的快捷指令
- 模拟键盘快捷键（Command+Tab, Control+Space 等）
- 调用系统服务（打开 Launchpad、Mission Control、通知中心）

## 八、待确认问题

1. **3×3 网格还是 2×2 更合适？** 9 个区域够细还是太碎？
2. **标定流程**：手动点击标定，还是坐下后自动检测"稳定期"自动标定？
3. **指尖位置**：用食指指尖（indexTip）还是手部中心点（wrist）做精确定位？
4. **区域选中是否需要锁定机制？** 即选中一个区域后，头轻微晃动不会立即切走，要超出阈值才切
5. **Pinch 单击的阈值**：捏合的间隔和时长，你希望偏灵敏还是偏稳定？
