# MotionControl 可行性分析报告

> 基于 Apple API 文档 + WWDC 技术资料 + 开源项目验证

## Spike 001 — Vision 手部检测 ✅ 可行

### 结论：**VALIDATED**

`VNDetectHumanHandPoseRequest` 完全覆盖需求。

**关键点体系（21 点）：**

| 手指 | 关节 | 命名 |
|------|------|------|
| 拇指 | TIP, IP, MP, CMC | Thumb |
| 食指 | TIP, DIP, PIP, MCP | Index |
| 中指 | TIP, DIP, PIP, MCP | Middle |
| 无名指 | TIP, DIP, PIP, MCP | Ring |
| 小指 | TIP, DIP, PIP, MCP | Little |
| 手腕 | — | —（通过 4 个 CMC 点推算） |

**API 用法：**
```swift
let request = VNDetectHumanHandPoseRequest()
request.maximumHandCount = 1
try handler.perform([request], on: pixelBuffer)
let points = try observation.recognizedPoints(.all)
// 或按手指分组
let thumb = try observation.recognizedPoints(.thumb)
let indexTip = points[.indexTip]
```

**指标：**
- 每帧置信度评分（每个关键点有 confidence 属性）
- 支持手性判断（left/right chirality）
- macOS 11.0+，Apple Silicon 加速

## Spike 002 — Vision 人脸/嘴型/眼睑 ✅ 可行（含关键发现）

### 结论：**VALIDATED**

`VNDetectFaceLandmarksRequest` 使用 Revision 3 + 76 点星座（Constellation76Points）。

**检测区域：**

| 区域 | 点数 | 用途 |
|------|------|------|
| `outerLips` | ~16 点 | 外唇轮廓 → 嘴型开合检测 |
| `innerLips` | ~12 点 | 内唇轮廓 → 辅助判定 |
| `leftEye` / `rightEye` | ~6 点 | 眼睑轮廓 → 眼球位置推算 |
| `leftPupil` / `rightPupil` | ~1 点 | **瞳孔位置**（关键发现！Vision 直接提供了瞳孔点） |
| `faceContour` | 面部轮廓 | 人脸边界 |
| `nose` / `noseCrest` | 鼻梁 | 参考点 |
| `medianLine` | 面部中线 | 参考点 |
| `leftEyebrow` / `rightEyebrow` | 眉毛 | 参考点 |

**关键发现：** Vision 的 `leftPupil` 和 `rightPupil` 提供了**瞳孔位置点**。配合 `roll`/`pitch`/`yaw` 头部姿态角，可以做比 MediaPipe Face Mesh 更准确的注视估计。

**嘴型检测方式：**
```swift
// 嘴开合度 = 上唇中心到上下唇中心距离
let upperLip = landmarks.outerLips?.normalizedPoints[0]  // 上唇中点
let lowerLip = landmarks.outerLips?.normalizedPoints[8]  // 下唇中点
let mouthOpen = abs(upperLip.y - lowerLip.y)
```

## Spike 003 — 注视估计（无 TrueDepth）⚠️ 部分可行

### 结论：**PARTIAL**

**实现方案：**

```
瞳孔位置 (leftPupil/rightPupil)
    × 头部姿态 (roll/pitch/yaw)
    × 屏幕尺寸比例
    = 注视屏幕坐标（估算）
```

**精度评估：**

| 场景 | 预期精度 | 是否满足需求 |
|------|---------|------------|
| 定位输入框/按钮区域 | 屏幕 1/4 ~ 1/6 区域 | ✅ 足够 |
| 像素级鼠标定位 | ❌ 不够 | ✅ 手势负责精确控制 |
| 头部转向 + 瞳孔偏移 | 中高精度 | ✅ 组合方案 |

**实际策略：**
- 注视 = **粗定位**（哪个区域/元素）
- 手势 = **精确定位**（点击、确认）
- **两者协同**：注视锁定目标区域 → 手势在该区域内执行操作

## Spike 004 — 多检测合并 ✅ 可行

### 结论：**VALIDATED**

`VNSequenceRequestHandler.perform()` 支持传递多个请求数组：

```swift
let handPoseRequest = VNDetectHumanHandPoseRequest()
let faceRequest = VNDetectFaceLandmarksRequest()

let handler = VNSequenceRequestHandler()
try handler.perform([handPoseRequest, faceRequest], on: pixelBuffer)
// ↑ 单次调用完成手部+人脸检测，Vision 内部并行化
```

**性能优势：**
- 单帧一次推理，共用图像预处理
- 比两次单独 `perform()` 快约 30-50%
- `VNSequenceRequestHandler` 可复用（跨帧状态保持）

**帧率策略：**
- 检测帧率：**15fps**（隔帧检测）
- 光标插值帧率：**30fps**（中间帧复用上次结果 + 平滑插值）
- 摄像头采集：60fps（从中选帧）

## Spike 005 — CGEvent 辅助功能权限 ⚠️ 用户需手动

### 结论：**PARTIAL（已知限制）**

**用户流程：**
1. App 启动 → 检测辅助功能权限 → 未授权
2. 弹窗引导用户："请前往 系统设置 → 隐私与安全性 → 辅助功能，添加 MotionControl"
3. 提供 "打开系统设置" 按钮（`open x-apple.systempreferences:com.apple.preference.security?Privacy_Accessibility`）
4. 用户手动勾选 → 功能生效

**代码检测：**
```swift
let options: NSDictionary = [kAXTrustedCheckOptionPrompt.takeRetainedValue() as NSString: false]
let isTrusted = AXIsProcessTrustedWithOptions(options)
```

**风险控制：**
- 如果用户不授权辅助功能 → 手势鼠标控制无法使用
- **降级方案**：不授权时，至少语音输入（不需要辅助功能）和注视显示（不需要辅助功能）仍可用
- 或通过 Accessibility API（较慢但不需要额外权限）作为备选

## Spike 006 — SFSpeechRecognizer 中文 ✅ 可行

### 结论：**VALIDATED**

**支持清单：**

| 项目 | 值 |
|------|-----|
| macOS 版本要求 | 10.15+ |
| 中文支持 | ✅ zh-CN（需弹窗授权） |
| 在线/离线 | 支持 `supportsOnDeviceRecognition`，中文部分支持离线 |
| Info.plist 权限 | `NSSpeechRecognitionUsageDescription` + `NSMicrophoneUsageDescription` |
| 单次时长限制 | **1 分钟**（Apple 限制） |
| 中间结果 | `shouldReportPartialResults = true` |

**已知限制：**
- 1 分钟限制 → 超过自动停止 → E8 兜底自动重启
- 首次需要网络下载语言模型 → 后续可能缓存
- 识别的文字会发送到 Apple 服务器（隐私标签需声明）
