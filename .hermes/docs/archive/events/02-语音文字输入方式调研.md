# 调研：语音识别文字如何输入到系统 — macOS 多种输入方式可行性

> 目标：语音转文字后，在 macOS 上输入到当前激活应用的多种方式，以及 App Store Sandbox 兼容性

---

## 背景

MotionControl 的语音识别输出的是**纯文本字符串**（来自 SFSpeechRecognizer 的 `bestTranscription`），不是键盘按键事件。把这个字符串"输入"到系统当前聚焦的输入框，在 macOS 上有**3 种技术路线**。

---

## 方案一：剪贴板 + 模拟粘贴 ✅ 推荐

### 原理
1. 保存当前剪贴板内容
2. 将语音文字写入 NSPasteboard
3. 模拟 ⌘+V 粘贴
4. 100ms 后恢复剪贴板

### 代码实现

```swift
func injectTextViaPaste(_ text: String) throws {
    // 1. 保存当前剪贴板
    let savedItems = NSPasteboard.general.pasteboardItems
    
    // 2. 写入语音文字
    NSPasteboard.general.clearContents()
    NSPasteboard.general.setString(text, forType: .string)
    
    // 3. 模拟 ⌘+V
    // ⚠️ 三种方式模拟粘贴
    try simulatePaste()
    
    // 4. 恢复剪贴板
    DispatchQueue.main.asyncAfter(deadline: .now() + 0.1) {
        NSPasteboard.general.clearContents()
        if let items = savedItems {
            NSPasteboard.general.writeObjects(items)
        }
    }
}
```

### 模拟粘贴的 3 种子方案

| 子方案 | 原理 | Sandbox | 权限 | 稳定性 |
|--------|------|---------|------|--------|
| **CGEvent** | `CGEventPost(.cghidEventTap, cmd+v)` | ❌ **被 Sandbox 屏蔽** | 辅助功能 | ⭐⭐⭐⭐⭐ |
| **AppleScript** | `tell System Events to keystroke "v" using command down` | ✅ **可用** | 系统事件控制 | ⭐⭐⭐⭐ |
| **Cocoa sendAction** | `NSApp.sendAction(#selector(NSText.paste(_:)), to: nil, from: self)` | ✅ **可用** | 无需额外权限 | ⭐⭐（仅 Cocoa App） |

### 关键发现：CGEvent 在 Sandbox 中被禁止

来自 QUICOPY 作者的实际踩坑经验：
> CGEvent.post() is completely blocked inside App Sandbox. There is no entitlement that re-enables it. Apple will not provide one.

因此 **App Store 版本必须使用 AppleScript + System Events**。

### AppleScript 方案的工作方式

```swift
let script = """
tell application "System Events"
    keystroke "v" using command down
end tell
"""
let appleScript = NSAppleScript(source: script)
var error: NSDictionary?
appleScript?.executeAndReturnError(&error)
```

**权限要求**：
- Info.plist 需添加 `NSAppleEventsUsageDescription`
- 首次使用弹窗："MotionControl wants to control System Events."
- 用户同意 → 可用
- 用户拒绝 → 降级：只能光标定位、手势操作，语音输入不可用

### 字符兼容性

| 字符类型 | 是否支持 | 说明 |
|---------|---------|------|
| ASCII（英文） | ✅ | 完美 |
| 中文 | ✅ | 完美（在 Pasteboard 中是 UTF-8 字符串） |
| 日文/韩文 | ✅ | 完美 |
| Emoji | ✅ | 完美 |
| 富文本 | ✅ | NSPasteboardItem 支持多种 type |
| 超长文本（>64KB） | ✅ | 支持，无限制 |

## 方案二：Accessibility API 直接设置值

### 原理
通过 `AXUIElementSetAttributeValue` 直接设置可编辑元素的 `kAXValueAttribute` 或 `kAXSelectedTextAttribute`。

```swift
func injectTextViaAccessibility(_ text: String) throws {
    // 1. 获取系统级 AX 元素
    let systemWide = AXUIElementCreateSystemWide()
    
    // 2. 获取当前聚焦元素
    var focused: CFTypeRef?
    AXUIElementCopyAttributeValue(
        systemWide, 
        kAXFocusedUIElementAttribute as CFString, 
        &focused
    )
    let element = focused as! AXUIElement
    
    // 3. 检查是否可编辑
    var role: CFTypeRef?
    AXUIElementCopyAttributeValue(element, kAXRoleAttribute as CFString, &role)
    let roleStr = role as! String
    guard roleStr == kAXTextFieldRole || roleStr == kAXTextAreaRole else {
        throw TextInputError.notEditable
    }
    
    // 4. 设置文本值
    AXUIElementSetAttributeValue(
        element, 
        kAXValueAttribute as CFString, 
        text as CFTypeRef
    )
}
```

### 评价
| 维度 | 评估 |
|------|------|
| Sandbox | ✅ 可用 |
| 权限 | ⚠️ 需要辅助功能 |
| 原生 App | ✅ Works（Safari、Notes、Xcode、Pages） |
| Electron App | ⚠️ 部分工作（VS Code 的某些输入框不支持） |
| Java App | ❌ 不支持 |
| WebView | ⚠️ 部分支持 |
| 中文 | ✅ 支持（Text as CFStringRef） |

⚠️ **不推荐作为主方案** — 跨 App 兼容性差，不同 App 的行为不一致。

## 方案三：CGEvent 逐字符按键模拟

### 原理
对每一个字符生成 `CGEvent` 键盘事件，模拟真实打字。

### 致命问题：不支持中文

CGEvent 模拟的是**键盘按键**，不是字符串。中文输入法需要组合编码过程（拼音→候选→选字），CGEvent 无法模拟这个流程。

```swift
func injectTextViaKeystrokes(_ text: String) {
    let source = CGEventSource(stateID: .hidSystemState)
    for char in text {
        // ❌ ASCII 字符可以，中文不能
        // 因为中文没有对应的 CGKeyCode
        let keyCode = charToKeyCode(char)
        let down = CGEvent(keyboardEventSource: source, 
                          virtualKey: keyCode, keyDown: true)
        let up = CGEvent(keyboardEventSource: source, 
                        virtualKey: keyCode, keyDown: false)
        down?.post(tap: .cghidEventTap)
        up?.post(tap: .cghidEventTap)
    }
}
```

### 评价
| 维度 | 评估 |
|------|------|
| 中文 | ❌ **不支持**（没有对应的 keyCode） |
| Sandbox | ❌ CGEvent.post() 被屏蔽 |
| 权限 | ⚠️ 需要辅助功能 |
| ASCII 性能 | 慢（每个字符 2ms×N） |

❌ **不推荐** — 不支持中文 + 不支持 Sandbox。

## 关于"多种输入法"的问题

### 问题本质

您问的是语音识别后的文字能否调用**系统的多种输入法**来处理。这里有两个层面的理解：

### 层面一：文字输出是否依赖当前输入法？

**答案：不依赖。**

`NSPasteboard + Cmd+V` 的工作方式不关心用户当前用的是 **ABC / 拼音 / 五笔 / 搜狗**。最终粘贴进去的是**已经转好的文字**，不管当前是什么输入法都生效。

```
┌─ 识别 ──┐   ┌─ 文字 ──┐   ┌─ 粘贴 ──┐   ┌─ 接收 ──┐
│ 语音说    │ → │ "打开   │ → │ ⌘+V     │ → │ Safari   │
│ "打开网站"│   │  网站"  │   │         │   │ 地址栏    │
└──────────┘   └─────────┘   └─────────┘   └──────────┘
当前输入法: 拼音 / 五笔 / 搜狗  →  ⚡ 无影响
```

### 层面二：能否切换输入法后再输入？

技术上可以通过 `TISSelectInputSource()` 在注入文字前切换输入法：

```swift
// 切换到 ABC 英文输入
func switchToInputSource(_ id: String) {
    let dict = [kTISPropertyInputSourceID: id]
    let sources = TISCreateInputSourceList(dict as CFDictionary, false)
    if let source = (sources?.takeRetainedValue() as? [TISInputSource])?.first {
        TISSelectInputSource(source)
    }
}
```

### 已知 Bug：TISSelectInputSource 后实际不生效

**这是一个已知的 macOS 问题，有多个开发者证实：**

> TISSelectInputSource 调用后，菜单栏图标变了，但真正打字时还是之前的输入法。必须切换到另一个 App 再切回来才生效。

影响范围：中文/日文/韩文等 CJVK 输入法，ABC 英文不受影响。

| 输入法 | TISSelectInputSource | 备注 |
|--------|---------------------|------|
| ABC（英文） | ✅ 正常切换 | 切换即生效 |
| Pinyin - Simplified | ⚠️ 图标变化但实际不生效 | 需切 App 才生效 |
| Sogou Pinyin | ⚠️ 同 | — |
| Wubi | ⚠️ 同 | — |
| Japanese (Hiragana) | ⚠️ 同 | 也有这个问题 |

### 层面三：是否需要"输入法"参与？

**不需要。** 因为 SFSpeechRecognizer 已经完成了语音→文字的转换，输出的是最终文字，不是拼音序列。所以不需要经过输入法再做一次拼音→文字的转换。

```
传统输入流程:  键盘敲拼音 → 输入法选词 → 文字上屏
我们的流程:    语音 → SFSpeechRecognizer → 文字 → 粘贴
                          ↑
                   这里已经完成了"选词"
```

## 推荐方案

### 主方案：AppleScript + 剪贴板粘贴

```
语音识别文字
    ↓
保存剪贴板 → 写入文字 → AppleScript 触发 ⌘+V → 恢复剪贴板
```

**为什么选这个：**
- App Store Sandbox ✅
- 中文完美 ✅
- 所有 App 兼容（Safari, Chrome, WeChat, VS Code, Terminal...）✅
- 剪贴板自动恢复，不影响用户 ✅

**权限成本：**
- 需 `NSAppleEventsUsageDescription` 权限描述
- 首次使用弹窗授权

### 回退方案：Accessibility API

如果 AppleScript 被用户拒绝（System Events 权限被拒），回退到 Accessibility API 方案，只能覆盖原生 Cocoa App。

### 纯键盘模拟（CGEvent）

**不支持中文 + 不支持 Sandbox**，此路不通。

---

## 结论

✅ **可行。推荐 AppleScript + 粘贴方案，覆盖所有 App 和 Sandbox 要求。**

不需要切换输入法，因为 SFSpeechRecognizer 已产出最终文字，直接粘贴即可。
