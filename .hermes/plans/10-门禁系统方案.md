# 门禁控制系统 — 方案设计

> 目标：让不遵守规范变得不可能，而不是"靠自觉"

---

## 三层门禁架构

```
你要改代码
    │
    ▼
第一层：Aider 入口拦截
  ├─ aider-runner.py 启动时检查 .hermes/plans/ 中
  │  是否有已确认的 plan 文件
  ├─ 无 plan           → ❌ 拒绝执行，"请先生成 plan"
  ├─ 有 plan 但未确认  → ❌ 拒绝执行，"请先展示给用户确认"
  └─ 有 plan 且已确认  → ✅ 放行
    │
    ▼
第二层：pre-commit hook
  ├─ 检查当前 commit 关联的 plan 文件是否存在且已确认
  ├─ 无关联 plan → ❌ 拒绝提交，"请关联 plan 文件"
  └─ 有关联 plan → ✅ 放行
    │
    ▼
第三层：你亲自看 commit
  ├─ 发你 "改动清单 + 计划文件" 预览
  └─ 你点头 → merge
```

---

## 实现方案

### 1. plan 确认标记

在 plan 文件末尾添加固定格式的确认标记：

```markdown
---

## 审批

状态：[✅] 已确认
确认人：小明
确认时间：2026-05-28
```

aider-runner.py 和 pre-commit hook 通过正则匹配 `\[✅\] 已确认` 来判断。

### 2. aider-runner.py 改造

在 runner 的最前面（`run_aider()` 调用前）插入检查逻辑：

```python
def check_plan_confirmed(workdir):
    """检查是否有已确认的 plan"""
    plans_dir = Path(workdir) / ".hermes" / "plans"
    if not plans_dir.exists():
        print("❌ 没有 .hermes/plans/ 目录，请先生成 plan")
        sys.exit(1)
    
    # 找最新的 plan 文件
    plan_files = sorted(plans_dir.glob("*.md"), key=os.path.getmtime, reverse=True)
    if not plan_files:
        print("❌ 没有 plan 文件，请先生成 plan")
        sys.exit(1)
    
    latest_plan = plan_files[0]
    content = latest_plan.read_text()
    
    # 检查确认标记
    if "✅ 已确认" not in content and "[✅] 已确认" not in content:
        print(f"❌ plan {latest_plan.name} 未确认，请先展示给用户确认")
        sys.exit(1)
    
    print(f"✅ plan {latest_plan.name} 已确认，放行")
```

### 3. pre-commit hook

脚本路径：`.git/hooks/pre-commit`

逻辑：
```bash
#!/bin/bash
# 检查当前提交是否关联已确认的 plan

# 获取暂存区中最新修改的文件
PLAN_DIR=".hermes/plans"
LATEST_PLAN=$(ls -t $PLAN_DIR/*.md 2>/dev/null | head -1)

if [ -z "$LATEST_PLAN" ]; then
    echo "❌ 没有找到 plan 文件"
    echo "   请先创建 plan 并确认"
    exit 1
fi

if ! grep -q "✅ 已确认" "$LATEST_PLAN" 2>/dev/null; then
    echo "❌ plan $LATEST_PLAN 未确认"
    echo "   请先展示给用户确认"
    exit 1
fi

echo "✅ plan $LATEST_PLAN 已确认，提交通过"
```

### 4. 安装脚本

`scripts/install-gates.sh`：一键安装 pre-commit hook + 配置 aider-runner.py。

## 权限分级控制

权限不是一刀切。把代码文件按**改动影响范围**分级，不同级别对应不同门禁。

### 权限等级定义

```
P-PARAM（参数级）: 改阈值、常量、颜色、配置值
  → 不需要 plan，可以直接调 Aider
  → 但 pre-commit hook 仍然要记录改动原因

P-LOGIC（逻辑级）: 改 if/else/循环/算法逻辑
  → 需要 plan + 确认标记
  → plan 中必须列出要改的所有文件

P-ARCH（架构级）: 新增文件/改接口/改协议/改架构
  → 需要 plan + 确认标记
  → plan 中必须包含 ASCII 流程图
  → 必须我先展示，你看完点头

P-BLOCKED（禁止级）: 永远不能动的文件
  → aider-runner 直接拒绝，hook 也拒绝
```

### 权限清单示例（PERMISSIONS.md）

需要在项目根目录放一个 `PERMISSIONS.md`：

```markdown
# MotionControl 代码权限清单

## P-PARAM（参数级，无需plan）
- Sources/MotionControl/Config/GestureConfig.swift
  - 改默认值、阈值、灵敏度参数
- Sources/MotionControl/Detection/GestureAnalyzer.swift
  - 改检测阈值常量

## P-LOGIC（逻辑级，需plan）
- Sources/MotionControl/Detection/GestureAnalyzer.swift
  - 改手势识别逻辑
- Sources/MotionControl/Control/CursorController.swift
- Sources/MotionControl/App/MotionControlApp.swift
- Sources/MotionControl/Detection/DetectionPipeline.swift

## P-ARCH（架构级，需plan+流程图）
- 新增 .swift 文件
- 改协议/接口定义
- 改类结构/继承关系

## P-BLOCKED（禁止级）
- Sources/MotionControl/Camera/CameraService.swift（不动摄像头层）
- Sources/MotionControl/Voice/*（不动语音模块）
```

### aider-runner 检查流程

```
① 读取本次要改的文件列表（--files 参数）
② 查 PERMISSIONS.md 确认每个文件的权限等级
③ 取所有文件中的最高等级：
   - 最高 P-PARAM → 直接放行
   - 最高 P-LOGIC → 检查 plan 已确认
   - 最高 P-ARCH → 检查 plan 已确认 + 有流程图
   - 有 P-BLOCKED → ❌ 拒绝，报告"无权修改此文件"
```
