## 教训沉淀

### 教训 1：Git 根目录是代码审计的第一道检查

**现象**：`swift package init` 创建的 .git 被 Aider 忽略，Aider 找到了用户主目录的 .git。

**规范**：新项目开工前，第一件事 `git rev-parse --show-toplevel` 确认 git root 就是项目目录。

### 教训 2：Aider 的 "Applied edit to" ≠ 文件真的写到了正确位置

**现象**：Aider 返回 exit code 0 + "Applied edit to X.swift"，但文件在项目目录里不存在。

**规范**：每次 Aider 运行后，`find ... -name "*.swift" -newer Package.swift` 验证文件确实在预期路径。

### 教训 3：短指令 ≠ 正确指令

**现象**：为了通过安全扫描，我把 Aider 指令缩到极短，结果 Aider 自由发挥写出错误内容。

**规范**：指令长度和安全审批之间有矛盾，需要找到平衡点。或者准备一份完整规格说明文件作为上下文传给 Aider。

### 教训 4：Swift 版本要提前确认

**现象**：Swift 6.3.2 移除了/更改了一些 API（MenuBarExtra 初始化器、Settings Scene、foregroundColor）

**规范**：`swift --version` 提前确认，对照 Swift evolution 检查 API 变更。macOS 26 = Swift 6。

### 教训 5：工具链故障时应有降级预案

**现象**：Aider 挂了 → 我打破规则写代码 → 虽然修好了但流程被破坏。

**规范**：约定好"如果 Aider 连续 3 次不起作用，允许直接写 fix-only 代码（不改逻辑，只修编译错误）"。
