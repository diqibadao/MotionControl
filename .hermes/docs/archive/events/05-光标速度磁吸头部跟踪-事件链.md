## 每个事件的完整处理链路

### E1：光标灵敏度调整

#### 1. 根因
当前光标位置映射公式（MotionControlApp.swift:143-144）：
```
targetX = (1.0 - tip.x) * screen.width * CGFloat(config.mouseSensitivity)
targetY = tip.y * screen.height * CGFloat(config.mouseSensitivity)
```
- `mouseSensitivity` 当前默认 8.0
- 用户手指从左到右移动，光标只覆盖 ~1/3 屏幕范围
- 原因是 `(1.0 - tip.x) * screen.width` 本身就是屏幕宽度（0~1→0~screenWidth），再乘 sensitivity=8.0 理论上应该超屏——但检查日志发现 targetX 实际值偏小

#### 2. 处理方案
**方案 A（推荐，改动最小）**：在公式上加额外 ×3 倍率
```swift
let multiplier: CGFloat = 3.0  // 或放到 config 中作为 'cursorSpeed' 参数
let targetX = (1.0 - tip.x) * screen.width * CGFloat(config.mouseSensitivity) * multiplier
let targetY = tip.y * screen.height * CGFloat(config.mouseSensitivity) * multiplier
```

**方案 B**：把 `mouseSensitivity` 默认值从 8.0 提到 24.0
纯参数改动（P-PARAM），但后续调整不方便

#### 3. 测试场景清单

| ID | 类型 | 输入 | 预期 | Mock | Teardown |
|----|------|------|------|------|---------|
| E1-T1 | 正向 | 手指从左滑到右 | 光标从左边缘到右边缘 | 无 | 无 |
| E1-T2 | 边界 | 手指快速大幅移动 | 光标不跳出屏幕 | 无 | 无 |
| E1-T3 | 边界 | 手指从屏幕左到右再到左 | 光标方向跟随正确 | 无 | 无 |

### E2：底部 Dock 图标磁吸

#### 1. 根因
`UIElementScanner.scan()`（第 145-146 行）：
```swift
guard let frontApp = NSWorkspace.shared.frontmostApplication,
      frontApp.activationPolicy == .regular else { return }
```
- 只扫描 `.regular` 激活策略的 App（普通窗口程序）
- **Dock 的激活策略是 `.accessory`**，所以永远不会被扫描
- 因此 Dock 图标不会被磁吸

#### 2. 处理方案
在 `UIElementScanner` 中添加专门的 Dock 扫描逻辑：
```swift
// 新增方法：扫描 Dock
func scanDock() {
    guard let dockApp = NSWorkspace.shared.runningApplications.first(where: { 
        $0.bundleIdentifier == "com.apple.dock" 
    }) else { return }
    let dockElement = AXUIElementCreateApplication(dockApp.processIdentifier)
    // 获取 Dock 的子元素（图标列表）
    // ...
}
```
Dock 的 AX 结构：
```
AXApplication "Dock"
  └── AXList "Dock"
       └── AXDockItem (每个应用图标)
            ├── AXButton
            └── kAXTitleAttribute = 应用名
```

#### 3. 测试场景清单

| ID | 类型 | 输入 | 预期 | Mock | Teardown |
|----|------|------|------|------|---------|
| E2-T1 | 正向 | 光标移到 Dock 附近 | 磁吸到最近的应用图标 | Mock Dock 元素 | 恢复原始 scan |
| E2-T2 | 正向 | 光标从 Dock 移开 | 磁吸释放 | 同上 | 同上 |
| E2-T3 | 异常 | Dock 被隐藏/自动隐藏 | 不崩溃 | Mock 空 Dock | 同上 |

### E3：头部姿态检测修复

#### 1. 根因
`FaceMeshDetector.swift` 第 76 行：
```swift
let request = VNDetectFaceLandmarksRequest()  // ← 这个 API 不返回 pitch/yaw/roll
```
调研确认：`VNDetectFaceLandmarksRequest` **从不返回头部姿态**（pitch/yaw/roll 始终为 nil）。

正确的 API：`VNDetectFaceRectanglesRequest` Revision 3（macOS 12+ / iOS 15+），Apple WWDC 2021 明确说明。

#### 2. 处理方案
在 `FaceMeshDetector` 中**保留 landmarks 检测**（面部 76 点用于嘴型/面部叠加），**新增**一个 `VNDetectFaceRectanglesRequest Revision 3` 来获取头部姿态：

```swift
// 面部特征点检测（现有，不动）
let landmarksRequest = VNDetectFaceLandmarksRequest()

// 新增：头部姿态检测
let faceRectRequest = VNDetectFaceRectanglesRequest()
faceRectRequest.revision = VNDetectFaceRectanglesRequestRevision3  // macOS 12+
// faceRectRequest.results[0].yaw → 连续方向值
// faceRectRequest.results[0].pitch → 连续方向值  
// faceRectRequest.results[0].roll → 连续方向值

// 合并两个 request 到同一个 handler
try handler.perform([landmarksRequest, faceRectRequest])
```

**注意**：需要改 `FaceResult` 结构体的初始化方式——从 `VNFaceObservation` 取姿态时，VNFaceObservation 的 roll/pitch/yaw 在 `VNDetectFaceLandmarksRequest` 结果中永远是 nil，但在 `VNDetectFaceRectanglesRequest` 结果中有效。

**实际上 VNFaceObservation 是同一个类**——所以可以从 landmarks 检测结果中读 landmarks（面部 76 点），从 faceRects 检测结果中读 pitch/yaw/roll。

#### 3. 头部+手部融合（模式C，后续实现）
修复姿态检测后，下一步实现粗→细融合：
```
头部 yaw/pitch → 大幅光标移动（粗定位）
手指 indexTip  → 精细微调 + 点击（精修）
```
融合方式：两个位置加权平均，头部权重随手指激活程度变化
- 手指未激活：纯头部控制（cursor = headPosition）
- 手指激活：cursor = headPosition × 0.4 + fingerPosition × 0.6

## 状态机/数据拓扑矩阵

### 光标控制状态机

```
                   手势不激活
                  ┌─────────┐
                  │  Idle   │ ←────────── 手丢失/手指弯曲
                  └────┬────┘
                       │ 手指伸出 + otherLow
                       ▼
                  ┌─────────┐    磁吸力距 < 35px    ┌─────────┐
                  │  Finger  │ ──────────────────→  │  Snap   │
                  │  Active  │ ←──────────────────  │         │
                  └─────────┘    拉力距 > 50px      └─────────┘
                       │
                       │ 头部姿态有效
                       ▼
                  ┌─────────────┐
                  │ Head+Finger  │ ← 融合模式C：头粗+手精
                  │  Fusion     │
                  └─────────────┘
```

| 状态转移 | Idle | Finger Active | Snap | Head+Fusion |
|---------|------|-------------|------|-------------|
| Idle → Finger Active | - | ✅ E1手指伸出 | - | - |
| Finger Active → Idle | ✅ resetCursor | - | - | - |
| Finger Active → Snap | - | - | ✅ E2磁吸35px | - |
| Snap → Finger Active | - | ✅ E2释放50px | - | - |
| Finger Active → Fusion | - | - | - | ✅ E3姿态有效 |
| Fusion → Finger Active | - | ✅ 姿态丢失 | - | - |
